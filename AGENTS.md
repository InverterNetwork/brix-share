# Brix Share

Zero-knowledge secret sharing. Spec: `docs/PLAN.md`. Every judgment call: `docs/DECISIONS.md` (add new ones there). Operations: `docs/RUNBOOK.md`. Setup, checks, dependency policy, workflow and roadmap: `CONTRIBUTING.md`.

## Layout (pnpm workspace)

- `shared/`: protocol constants, strict base64url, AAD builders, Zod schemas, `validateCreateRequest`, API error codes, known-answer vectors (`vectors/kat-v1.json`, generated by `scripts/gen-vectors.ts`). Exports TypeScript source; no build step.
- `api/`: the single Lambda behind CloudFront at `/api/*` (Function URL + OAC).
- `sweeper/`: 5-minute Lambda cleaning expired items and orphaned file objects.
- `web/`: Vite + Preact SPA. All cryptography lives here (WebCrypto).
- `infra/`: CDK app. Stage config is not in the repo: `infra/stages.json` (git-ignored) comes from the `STAGES_JSON` repository variable; `infra/stages.example.json` shows the format and drives CI and tests (`BRIX_SHARE_STAGES` picks the file).
- `design/`: brand tokens and logos. Reference only. Fonts live in `web/src/assets/fonts`.

## Commands

Node 22 via fnm (`.nvmrc`), pnpm via corepack.

- `pnpm install`
- `pnpm lint` (ESLint type-checked + Prettier check), `pnpm format`
- `pnpm typecheck`, `pnpm test`, `pnpm build`
- `BRIX_SHARE_STAGES=infra/stages.example.json pnpm synth` (CDK synth with the example stage config, no AWS credentials needed)
- `pnpm --filter @brix-share/shared check-vectors` (CI fails if `kat-v1.json` drifts from its generator)
- `pnpm --filter @brix-share/web e2e` (Playwright suite in Docker)

## Rules

- No crypto libraries. Browser: WebCrypto only. Server: `node:crypto` for hashing and HMAC only.
- Dependencies: only the approved list in `CONTRIBUTING.md`, exact versions, pnpm with the 7-day `minimumReleaseAge`. Anything else needs maintainer approval first. Build scripts are allowlisted in `pnpm-workspace.yaml` (`allowBuilds`).
- Never log request bodies, manage tokens, envelopes, ciphertext or presigned URLs. Never put IP addresses in the table.
- Existing vectors in `shared/vectors/kat-v1.json` are frozen for protocol v1 (new cases may be added; changing an existing one means a new protocol version). Fixed keys and IVs exist only in `shared/scripts/gen-vectors.ts`; real code always uses `crypto.getRandomValues`.
- The manage token travels in the `x-manage-token` header, never in a URL query string (`Authorization` is taken by CloudFront OAC signing).
- Imports use explicit `.ts` extensions (Node type stripping runs the CDK app and scripts directly).
