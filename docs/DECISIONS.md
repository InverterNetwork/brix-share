# Decisions log

One entry per judgment call: date, decision, reason. Plan-level decisions are in `docs/PLAN.md` section 16. Entries are historical; a later entry can supersede an earlier one.

- 2026-10-09: pnpm 11 build-script allowlist uses `allowBuilds` in `pnpm-workspace.yaml` (`esbuild` only). Reason: pnpm 11 replaced `onlyBuiltDependencies`; same intent.
- 2026-10-09: `minimumReleaseAge: 10080` set in `pnpm-workspace.yaml` as well, so the 7-day cooldown also holds in CI and on machines without a global config.
- 2026-10-09: TypeScript pinned to 6.0.3, not 7.x. Reason: typescript-eslint 8 supports `<6.1`.
- 2026-10-09: Preact 10.29 without `@preact/preset-vite`. Reason: Vite's built-in JSX transform (`jsxImportSource: preact`) suffices and avoids pulling in Babel; Preact 11 was inside the cooldown window anyway.
- 2026-10-09: `@types/node` added as a dev dependency although it was not on the original approved list. Reason: types only, no runtime code, and a peer of approved packages (Vitest, CDK). No other unlisted packages: Lambda event types and `qrcode` types are written by hand instead of `@types/aws-lambda` / `@types/qrcode`; ESLint uses typescript-eslint configs only (no `@eslint/js`, no `globals`).
- 2026-10-09: `shared` exports TypeScript source directly; Vite, esbuild, Vitest and Node type stripping consume it. No build step, no dual package.
- 2026-10-09: CDK app runs via Node 22 type stripping (`node --experimental-strip-types bin/app.ts`), no ts-node/tsx. Imports therefore use explicit `.ts` extensions repo-wide.
- 2026-10-09: Stage config (accounts, domains, zone ids) lives only in `infra/stages.json`, read by `bin/app.ts`; explicit env, no lookups. Reason: synth needs no credentials, and that one file can be swapped out for another deployment. (Since 2026-10-11 the file is not in the repository, see below.)
- 2026-10-09: `fileId` has the same format as `id`: 16 random bytes, base64url, 22 chars.
- 2026-10-09: Base64url decoding is strict and canonical (no padding, no stray trailing bits), so one byte string has exactly one accepted encoding.
- 2026-10-09: ISO-8601 inputs must be UTC (`Z`); fractional seconds are floored to whole seconds before bound checks.
- 2026-10-09: Known-answer vectors are generated with WebCrypto by a standalone script that types out the protocol strings instead of importing them, recorded with intermediates (NFC passphrase bytes, PBKDF2 output, K_data, exact plaintext bytes), and verified in tests by `node:crypto` plus RFC 5869, RFC 7914 and GCM test case 16 anchors. Negative vectors (bit flips, swapped id, flipped passphrase flag, wrong passphrase, `v2`, wrong fileId) are included for the client's tamper tests. Reason: this checks envelope assembly independently of the code under test; running the vectors in browser engines gives the primitive-level cross-check.
- 2026-10-09: Manage token travels in an `x-manage-token` header instead of `Authorization: Bearer`. Reason: CloudFront OAC for Lambda Function URLs signs requests with SigV4 in the `Authorization` header, so the plan's header cannot reach the function. Same properties: header, never query string, excluded from logs.
- 2026-10-09: Status response carries a few fields beyond the plan's list (`hasPassphrase`, `fileCount`, `endedAt`, `endedReason`, `historyUntil`) so the manage page can render live and tombstone states without guessing.
- 2026-10-09: Prettier does not format Markdown; docs are written by hand and `docs/PLAN.md` must not be reflowed.
- 2026-10-09: Deployment is manual, not CI-based. Reason: security; CI holds no AWS write access. No GitHub OIDC deploy roles and no deploy workflow. A human deploys infra and API with `cdk deploy` under SSO, and uploads the web build with a script that assumes `BrixShare-<stage>-web-deploy`, the only principal the static bucket accepts writes from. CI keeps checks, release asset hashes and the external monitor.
- 2026-10-09: A stage is two CloudFormation stacks (`BrixShare-<stage>-edge` in us-east-1 for certificate and WAF, `BrixShare-<stage>` in eu-central-1), plus `BrixShare-prod-zone` in us-east-1 for the delegated `share.brix.money` zone so it can be created and delegated before the certificate waits on DNS. Reason: CloudFront requires us-east-1 for both certificate and WAF.
- 2026-10-09: Metrics come from CloudWatch log metric filters over one-JSON-object-per-line stdout logs, not EMF or PutMetricData. Reason: no CloudWatch SDK dependency.
- 2026-10-09: The proof-of-work HMAC key is self-provisioned by the api Lambda as an SSM SecureString (`PutParameter` with `Overwrite: false` on first cold start). No secret in templates, repo or Lambda environment. Survives stack deletion; the runbook covers removing it.
- 2026-10-09: Adaptive difficulty and circuit breaker run in a `governor` Lambda driven by create-rate alarm state-change events plus a 15-minute schedule, state kept in SSM. Sustained = in ALARM for 60 minutes at maximum difficulty (24).
- 2026-10-09: WAF cannot read whole 128 KB bodies on CloudFront, so it enforces the cap on the `Content-Length` header (exact regex for values above 131072); the Lambda enforces it on the actual body.
- 2026-10-09: SSM parameter defaults (`createEnabled`, `powDifficulty`) live in the template. CloudFormation rewrites the live value whenever any property of that parameter resource changes (value, description, tags), so never deploy changes to those resources while the breaker or a raised difficulty is engaged (runbook).
- 2026-10-09: All recommended CDK feature flags of aws-cdk-lib 2.272 adopted before the first deploy. Reason: flipping them later replaces resources.
- 2026-10-09: Estimated-charges alarm is an AWS Budget on the `app=brix-share` cost allocation tag, opt-in per stage (`budgetUsd`). Reason: account-wide `EstimatedCharges` would be noise in a shared account.
- 2026-10-09: Static bucket keeps versioning with 30-day noncurrent expiry so what was served can be reconstructed after an incident; `s3:DeleteObjectVersion` is denied to everyone.
- 2026-10-09: Only the account's admin SSO role (pattern per stage in the stage config) may assume the web deploy role and read CloudFront access logs. File objects are readable only by the api role (presigned GETs). Changes to bucket policies by other privileged roles are detected by the external change monitor.
- 2026-10-09: WAF path matches URL-decode and lower-case the path; the API router 404s anything but the exact lower-case, unencoded path (no trailing slash), so no path variant reaches a route while skipping its rate rule.
- 2026-10-09: Governor "sustained" means 60 minutes in ALARM at difficulty 24 (counted from reaching 24 or entering ALARM, whichever is later); schedule steps tolerate 60 s of early firing. No throttle alarm for the governor (concurrency 1, two triggers, overlaps are retried).
- 2026-10-09: Cross-stack references are CDK "weak" references (`Fn::GetStackOutput`): no export locks and no custom resources, but the main stack must be redeployed after a change to the edge stack's certificate or ACL.
- 2026-10-09: The web UI must work and look good on mobile: responsive layouts, and the Playwright suite runs on phone viewports too.
- 2026-10-09: `deleteTokenHash` is SHA-256 over the 32 decoded token bytes (PLAN 6 defines `T_manage` as bytes), computed by the shared `hashManageToken` on both sides.
- 2026-10-09: Unlimited secrets keep the first 100 retrievals in the log (PLAN 8 cap) and count all of them in a `retrievalCount` attribute, so the manage page stays truthful past 100.
- 2026-10-09: Tombstones keep the original policy expiry in `policyExpiresAt`, since `expiresAt` becomes the history TTL. (Superseded by the `purgeAt` data-model correction below: `expiresAt` stays the policy expiry.)
- 2026-10-09: DELETE on a live item past its expiry records `expired` and answers 204 (the secret is gone either way); DELETE on an item already ended answers 404.
- 2026-10-09: DynamoDB writes use a client with `maxAttempts: 1` (reads keep SDK retries). Reason: a retried conditional decrement after a lost response would burn a second view for one envelope; an ambiguous write is a 500 and a burnt retrieval instead.
- 2026-10-09: `retrievalCount` and the retrieval log record committed consume writes, not confirmed deliveries to a browser.
- 2026-10-09: The reveal page shows no policy before the "Reveal secret" click. Reason: showing "can be opened N more times" up front would need a public, non-consuming read on page load, which link previews and scanners would hit and which hands policy to anyone holding the id. The generic copy says opening counts as a retrieval; views left and expiry appear after retrieval. (Partly revised in v1.1, see 2026-10-10: the availability check on load.)
- 2026-10-09: Generated passphrases use the EFF large wordlist (7776 words minus the four hyphenated ones = 7772), 5 words = 64.6 bits. Reason: PLAN 6 names the short list but quotes ~64 bits, which only the large list delivers (the short list gives 51.7 bits).
- 2026-10-09: The browser derives server time from the `Date` header of API responses; expiry presets are computed after the proof-of-work with a 60 s margin under the 30-day cap.
- 2026-10-09: The wordlist is bundled into the SRI-covered entry chunk (`inlineDynamicImports`); the PoW worker is the only script without SRI and handles no key material.
- 2026-10-09: Pure-JS SHA-256 in the PoW worker (about 10x faster per nonce than async WebCrypto digest); not used for anything secret, the server re-verifies with `node:crypto`.
- 2026-10-09: Playwright runs locally in the official Playwright Docker image (`web/scripts/e2e-docker.sh`), so no browser system libraries need to be installed on the host; CI installs browsers with dependencies on the runner.
- 2026-10-09: In the Playwright Firefox project the test server omits `Cross-Origin-Opener-Policy` (requested by a test-only header). Reason: Playwright's Firefox driver intermittently loses a navigation across the process swap that COOP triggers (about 1 in 13 navigations hung; 0 in 21 without COOP). Real Firefox is unaffected; COOP stays in production and is asserted by the header tests in the other four projects.
- 2026-10-09: Passphrase rule for protocol v1: trim surrounding whitespace (ECMAScript `String.prototype.trim`: WhiteSpace and LineTerminator incl. NBSP and U+FEFF), then NFC (`normalizePassphrase` in shared), on both sides. Reason: mobile keyboards append spaces after predicted words. PLAN 6 originally said NFC only; this was fixed before any v1 secret existed and is pinned by the `text-passphrase-whitespace` vector.
- 2026-10-09: The passphrase meter gives a bit count only for an unchanged generated phrase; anything typed or edited gets a warning, never a rating. Reason: a dictionary or character-class heuristic says nothing about how a phrase was chosen. Generated phrases stay at 5 words (64.6 bits, behind PBKDF2 600k) per PLAN decision 5, although EFF now suggests 6.
- 2026-10-09: The client rejects envelopes whose passphrase flag and salt disagree, and key derivation refuses a passphrase without salt (or the reverse) instead of falling back to the link key.
- 2026-10-09: Leaving the reveal page while a retrieved secret is held (passphrase prompt or decrypted view) asks for confirmation (in-app navigation, back/forward, tab close). The last created secret's links stay in App memory so back from the manage page shows them again.
- 2026-10-09: Playwright allows one retry per test. Reason: browser drivers occasionally lose a navigation (Firefox with COOP, see above; once in WebKit: 1 hang in 163 runs). Retried tests appear as "flaky" in the report and must be looked at, not ignored: a retry can hide a real intermittent bug. A test failing twice fails the run.
- 2026-10-09: Releases are `v*` tags on `main`; CI builds twice and publishes the manifest on a GitHub release. A human deploys a tag with `scripts/deploy-web.ts`, which refuses a local build that differs from that manifest. The deployed tag lives in the repository variable `DEPLOYED_<STAGE>` so the monitor needs no AWS access.
- 2026-10-09: The external monitor checks files and headers on `/`, `/index.html`, SPA paths and every release file. Known limitation: it is not proof of absence (cloaking by client IP is invisible to it), so the runbook keeps `verify-live` from a laptop as the spot check.

- 2026-10-09: Sweeper orphan rule: only object prefixes without any item are orphans (PLAN 9.6 said "ended or missing"); ended items are cleaned on `endedAt` plus 5 minutes. Reason: object age says nothing about a download that started just before the end. Stale pending items are deleted item-first, objects second. (Extended below.)
- 2026-10-09: A secret may consist of files only (empty text). Files are offered as `application/octet-stream` Blob downloads under sanitised names; automatic download start is best effort (browsers gate multiple downloads), Save links are the dependable path. (Superseded in v1.1: downloads start only on click.)
- 2026-10-09: The secret item stores `fileSizes` (declared plaintext sizes) so finalize can check every uploaded object; additive attribute.
- 2026-10-09: Data-model correction from the security review: with DynamoDB TTL on the policy expiry, TTL could delete an expired live item before anything tombstoned it (always for unread text-only secrets), losing the promised 30-day history and, for files, cutting the download grace short. Now the TTL attribute is `purgeAt` (live: expiry + 30 d; tombstone: `endedAt` + 30 d), `expiresAt` stays the policy expiry, and the sparse `sweep-due` index (`sweepPart` = `live` | `files`, `sweepAt`) replaces `files-by-expiry` so the sweeper tombstones every expired secret and deletes due files. Made before the first deploy, so no data had to be migrated. `docs/PLAN.md` section 8 is updated accordingly.
- 2026-10-09: Sweeper every 5 minutes (was hourly): expired envelopes and the files of ended secrets leave within minutes. Timeout 2 minutes so runs never overlap.
- 2026-10-09: Orphan rule extended: a bucket prefix is deleted when its item is missing or ended more than 5 minutes ago (objects older than 5 minutes). Reason: covers objects written again with a still valid upload URL after a delete.
- 2026-10-09: The client starts all attachment downloads at once under one shared byte budget (the 2-minute URLs are checked when a request starts), reads every API response through a 512 KB bound and puts deadlines on requests (60 s API, 10 min per file).
- 2026-10-09: README and the How it works page state that view limits, release dates, expiry and deletion are server-enforced: a compromised backend could ignore them, but still could not read secrets without the link key (and passphrase).
- 2026-10-09: Known limitation (protocol change, on the roadmap): file objects left for a few minutes after a secret ends can be decrypted with a later-leaked link. Fix: per-file random keys carried inside the encrypted payload. Mitigated meanwhile by deleting files within minutes of the end.
- 2026-10-09: Security review, second pass: fixed: download budget refunded on a failed attempt; leave guard from the moment the consume is sent; sweeper skips live prefixes (keys-only query of the live partition) and logs the item count before sweeping; HMAC key reloaded at most once a minute when a challenge signature does not match (rotation converges across containers); `verify-live` checks a client-sent `CloudFront-Viewer-Country` is ignored; API role loses `dynamodb:DeleteItem`; a daily creates alarm (over 2000 per 24 h); download names also lose C1 controls, bidi overrides and trailing dots/spaces; docs state that path-only observers can burn retrievals. Declined: a customer-managed KMS key for the HMAC parameter (a privileged reader can only skip the challenge rate limit; the hashing cost stays), pinning the download host in the client (the CSP from trusted delivery already does), claiming the challenge after the item write (only matters on a 2^-128 id collision).
- 2026-10-09: Known limitation (protocol change, on the roadmap): someone who knows only a link's path can burn its retrievals without being able to read it. Fix: a consume token derived from `K_link`, stored hashed like the manage token. Documented as a residual meanwhile.
- 2026-10-10: Per-file keys and the consume token are follow-ups after launch rather than launch blockers. Reason: both can be added backward compatibly (new secrets use them, old secrets keep the current path until they expire within 30 days, then the fallback is removed).
- 2026-10-10: Changes after the first production use (release v1.1.0):
  - New `GET /api/secrets/{id}`: answers 200 `{ availableFrom }` (null once released) or the same 404 as consume, never counts a retrieval and never returns the envelope (projected read). The share page calls it on load, so a deleted, used-up or expired secret shows as gone at once and a release-later secret shows its countdown without a click. Known limitation: someone who knows only the link's path can now poll silently whether a secret was opened, deleted or released, where before finding out burned a retrieval that the manage page shows. Small next to the documented path-only residual (they can burn it); the planned consume token can gate this endpoint too. Covered by the global WAF rate limit. If the check fails, the page falls back to the Reveal button.

Browsers drop session storage with the tab, but restore it with a reopened tab or a restored session (Firefox keeps it in its session file); a duplicated tab inherits it. Deviation from PLAN 6 ("nothing in sessionStorage"), limited to the manage token (status and delete, never content). Share-link keys stay in memory only. Plus a Refresh button.
  - Attachments no longer download on their own (PLAN 9.5 said auto-start); each file has a Download button.
